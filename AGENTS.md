## Project overview
First-come-first-served online admission system for a single government school. Guardians hold a seat (timed HOLD), confirm via simulated payment, or cancel; holds auto-expire. Must handle thousands of concurrent applicants with **zero overbooking**, even across multiple backend instances.
Backend: C# .NET 10 + PostgreSQL (EF Core + raw SQL on the critical path), Docker Compose. Frontend (React/Vite) is a separate workstream.

## Known issues / assumptions
- Assumptions agreed so far (to be copied into `ASSUMPTIONS.md` in Step 14): see decisions D8–D10, D12.
- Git repository initialised by the user (2026-11-11); the agent never runs git write commands (D13).
- Installed SDK: .NET 10.0.114; Docker available (needed for Testcontainers and compose).
- `heldSeats` in class responses excludes expired-but-unswept holds (computed at read time), so it can be lower than the stored counter for ≤ sweep interval — by design.
- `X-Student-Id` accepts ASCII digits only; Bengali numerals (০-৯) are rejected with 400 (frontend should convert or instruct). Surrounding whitespace is trimmed. → `ASSUMPTIONS.md`.
- `expiresAt` is returned with full DB precision (microseconds), e.g. `2026-11-11T04:10:00.123456Z` (valid ISO-8601).
- Frontend countdown note: the server is authoritative for expiry; Kestrel sends a standard `Date` response header the frontend can use to correct client clock skew. After expiry, `GET /holds/{id}` / `GET /me/holds` report `EXPIRED` immediately.
- `GET /me/holds` returns the full history (all statuses), unpaginated — a student has only a handful of applications.
- Connection budget resolved (D14): `Maximum Pool Size=50` per backend instance, Postgres `max_connections=200`.
- **Frontend in compose:** the `frontend` service (nginx, port 3000→80, build arg `VITE_API_BASE_URL`, waits for a healthy backend) is enabled. Default CORS allows `http://localhost:5173` (Vite dev) and `http://localhost:3000` (container); `Date` is exposed (D15).
